On this symbol's recorded tick size of 0.01, 300 points correspond to approximately 3.00 in price **if the broker's _Point is also 0.01**, as indicated by the two-decimal quote precision in the exported bars. Confirm the live symbol specification before carrying these point distances to another broker or symbol.

### What the code actually calculates

- Scenario entry is based on the signal bar's close, with scenario tracking updated on subsequent processed closed bars.
- For each scenario, gross points are calculated from exit price versus entry price and direction.
- The code then subtracts InpSimCostPoints once. Therefore net_points = gross_points - estimated_cost_points; do not subtract the 30-point cost a second time.
- The OHLC simulation is conservative when both TP and SL are touched in the same candle: the SL branch is evaluated first and wins.
- If a scenario remains open through 120 bars, it exits at that bar's close.
- The 30-point cost is a flat estimate. It is not a live reconstruction of spread, commission, swap, slippage, latency, or execution quality.
- Grid and pyramiding are simplified equal-size add simulations. They are not a full portfolio/margin/liquidation model.
- The money-stop simulation depends on symbol tick value, account currency, and lot size. The source itself warns that its USD stop is not USD-accurate when the account currency is not USD.

## 5. Stage 1 interpretation

1. **Best research candidate in the earlier sample:** BUY bounce from EMA100 with M5 EMA-stack alignment (n=73, PF=1.48, win rate 64.4%, average net +56.3 points). This is a candidate for further testing, not a proven live edge.
2. **EMA50 deserves a follow-up:** filtered BUY and SELL groups had PF values above 1 in the earlier calculation, but the samples and time alignment need independent validation.
3. **EMA15 alone was weak:** the earlier fixed TP/SL comparison showed PF below 1 for both directions, including the M5-filtered subsets.
4. **Core trend-pullback logic was weak under the tested fixed TP/SL model:** the earlier BUY and SELL groups had PF below 1 overall. Filtering did not consistently repair the result.
5. **Very small filtered groups are unstable:** EMA100 touch subsets with n=15–19 can show attractive PF/win rate by chance. They are not sufficient to select a production rule.
6. **No live-trading conclusion:** the sample is short, the cost model is simplified, the M1 source snapshot is currently missing, and the earlier metrics need exact reproduction.

## 6. Limitations and validation required before Stage 2

- Restore or re-export the four M1 files from the terminal's V3.1 collector, then verify their headers, row counts, date ranges, and status distributions.
- Restore M5 Events and Scenarios if those exports are expected to be part of the analysis. The current M5 Outcomes file is populated, but it is an excursion dataset, not the scenario P/L dataset.
- Re-run all calculations from the actual CSVs using the companion script as a first-pass audit. Extend the calculation once the missing source exports are restored.
- Rebuild the M1-to-M5 join with a strict timestamp rule: use only the most recent **fully closed** M5 candle available at the M1 signal timestamp. No future M5 candle values may enter the filter.
- Recompute every scenario family from the Scenarios.csv rows, grouping by scenario, event type, direction, and filter. Check that net points already include the flat cost exactly once.
- Report confidence intervals or resampling stability for promising small groups, and separate in-sample selection from an untouched validation window.
- Before any EA code change, the user must specify and confirm the exact target branch and file. This analysis step makes no code changes.

## 7. Reproduction

Run from any machine with Python 3.10+:

~~~bash
python V3.1_Stage_1_Analysis.py
~~~

By default, the script looks for the original eight CSV files in the parent folder of V3.1_Analysis (the TRX root), audits missing/empty/populated files, summarizes bars and outcome excursion groups, and summarizes scenario P/L if scenario exports are present.

To point it at a different folder:

~~~bash
python V3.1_Stage_1_Analysis.py --data-dir /path/to/TRX
~~~

To also save the audit as JSON:

~~~bash
python V3.1_Stage_1_Analysis.py --json-out stage1_audit.json
~~~

The script uses only the Python standard library and never edits the source CSVs.
